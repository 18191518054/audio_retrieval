# 本地 BGM V2 检索验证版

这是一个面向低资源 Windows 电脑的本地检索实验工具。它只索引音频，不移动、修改或删除源文件。

## 能力边界

- 本地目录扫描与增量更新
- SQLite 断点建库
- CLAP 中文文本搜音乐、以歌搜歌
- 文件名关键词与语义相似度混合排序
- 格式、时长过滤和浏览器直接试听
- 单进程、逐首推理，默认优先节省内存

本验证版有意不包含账号、项目、个性化、波形预计算、文件监听、桌面安装包和复杂任务队列。

## 使用 Conda 安装（推荐）

当前电脑已经安装 Conda。首次使用，在 Anaconda Prompt 或能够执行 `conda` 的 PowerShell 中运行：

```powershell
.\安装Conda环境.ps1
```

该脚本根据 `environment.yml` 创建名为 `bgm-v2` 的 Python 3.12 环境，并安装 PyTorch、Transformers、NumPy 和 FFmpeg。检测到 NVIDIA 显卡时默认安装 PyTorch 2.6 CUDA 12.4 版；没有 NVIDIA 显卡或提前设置 `BGM_TORCH_VARIANT=cpu` 时安装 CPU 版。模型、pip 缓存和临时文件均保存在项目的 D 盘目录。

以后启动只需运行：

```powershell
.\Conda启动本地检索.ps1
```

然后访问 <http://127.0.0.1:8765>。前端已经嵌入 Python 服务，不需要安装 Node.js，也不需要另开终端启动前端。

若 PowerShell 找不到 Conda，请改在 Anaconda Prompt 中执行，或先运行 `conda init powershell`，关闭并重新打开 PowerShell。

若系统阻止 PowerShell 脚本执行，可以使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\安装Conda环境.ps1
powershell -ExecutionPolicy Bypass -File .\Conda启动本地检索.ps1
```

### 是否需要配置

默认不需要任何配置。数据库写入项目的 `data/`，服务仅监听本机 `127.0.0.1:8765`，FFmpeg 由 Conda 环境提供。

需要修改端口、数据库目录或使用离线模型时，将 `local-config.example.ps1` 复制为 `local-config.ps1` 并修改。启动脚本会自动加载它。

CLAP 模型默认使用 `laion/clap-htsat-unfused`。首次使用会从 Hugging Face 下载模型；之后可以完全离线运行。可用 `BGM_CLAP_MODEL` 指向已下载的本地模型目录。

推荐标签分类默认使用本地模型，原有离线行为不变。若希望改用阿里云音频模型，在 `本地配置.ps1` 中加入：

```powershell
$env:BGM_RECOMMENDED_PROVIDER = "aliyun"
$env:DASHSCOPE_API_KEY = "你的 API Key"
$env:DASHSCOPE_BASE_URL = "https://dashscope.aliyuncs.com/compatible-mode/v1"
$env:BGM_ALIYUN_MODEL = "qwen3.8-omni-flash"
$env:BGM_CLOUD_MIN_CONFIDENCE = "0.78"
$env:BGM_CLOUD_FALLBACK_LOCAL = "1"
```

修改后需重启服务。云端模式只替换“推荐标签”的自动判断；检索向量、UCS、乐器/材质和自定义标签逻辑保持不变。系统抽取多个短音频片段上传，要求模型只能返回当前推荐标签树中的节点；低于置信度阈值时保持空白。调用结果按素材修改时间、模型和标签树版本缓存在 `library.db`，相同素材不会反复调用；标签树或素材变化时缓存自动失效。网络或接口异常时默认回退本地算法，若设为 `$env:BGM_CLOUD_FALLBACK_LOCAL = "0"` 则直接让建库任务报告错误。云端模式会产生服务费用并将抽样音频发送到服务商；默认 `local` 不上传任何音频，也不需要 API Key。

## 快速开始

```powershell
.\Conda启动本地检索.ps1
```

浏览器打开 <http://127.0.0.1:8765>，依次执行：

1. 添加素材目录并扫描；
2. 在“建向量”区域选择 CLAP；
3. 等待后台处理后输入自然语言搜索；
4. 可以选择一首本地音频作为参考歌。

如果希望手动进入环境，命令行也可以使用：

```powershell
conda activate bgm-v2
python -m bgm_v2 scan "D:\BGM"
python -m bgm_v2 index --provider clap --limit 100
python -m bgm_v2 search "克制的悲伤，适合人物独白" --limit 10
```

先用 100–500 首验证效果，再逐步扩大。CPU 建库会慢，但已经完成的歌曲不会重复处理。

可通过 `BGM_DATA_DIR` 修改。删除数据库只会清除索引，不会影响源音频。

## 本地标签分析

“一键建立检索库”会先用 CLAP 生成自然语言与参考音频检索向量，再释放模型内存并执行本地标签分析：

- AudioSet AST 先判断音乐或音效/环境声，再识别有明确证据的乐器；
- 节奏和 BPM 由本地音频信号计算；
- 情绪、场景仅在模型存在对应类别且超过较高阈值时保存；
- 无可靠结果时显示“无可靠标签”或“类型待确认”，不会硬凑两个标签。

界面不再提供没有语义能力的诊断模式，也不要求分别操作向量和标签流程。资源有限的电脑会依次加载模型，不会同时常驻两个大型模型。

扫描目录时必须指定“音乐”或“音效”。音乐自动生成四类一级标签——节奏（BPM）、乐器、情绪、风格；每类下采用固定的中文二级标签。音效使用下述四套树形标签进行筛选。旧数据库升级后原有素材为“未分类”，重新扫描相应目录并选择类型即可更新，不会删除源文件。

## 音效树形标签

音效支持四个并列的标签体系：

- `UCS 行业标准`：内置并缓存 UCS v8.2.1 的 82 个 Category、753 个 SubCategory，保留官方英文名称与 CatID。
- `推荐标签`：启动时从内置的 `bgm_v2/resources/recommended_taxonomy.json` 同步完整中文树，发布和运行均不依赖 XMind。
- `乐器/材质`：内置固定业务词表；第一层为“乐器”和“材质”，再细分常见配乐乐器、世界民族乐器、电子声源，以及音效拟音所需的金属、木材、玻璃、织物、液体等材质。
- `用户自定义标签`：可建立任意深度的个人树，支持新增子标签、重命名、删除整棵子树。

扫描音效时会读取标题、描述、关键词、艺术家、专辑等内嵌元数据，并保存在本地数据库。建立检索库时采用准确率优先策略：UCS 优先使用官方 CatID/Category/SubCategory 的精确元数据，无法精确匹配时，再与推荐标签、乐器/材质一起通过 CLAP 在当前标签树中动态分类。分类不包含具体关键词到标签的固定映射；只有得分和领先差距均达到严格门槛时才会写入，低置信素材保持未标记。自定义标签始终只由用户手工管理。

启用阿里云推荐标签提供方后，UCS也采用同一云端模型补全，但不会覆盖人工标签或确定性证据。顺序为：人工确认 > 正式CatID/Category/SubCategory元数据 > 标准UCS文件名前缀 > UCS官方名称或同义词的唯一文本命中 > 云端分层判断。云端先从一级Category中选择，再只在该Category直属SubCategory中选择现有节点；一级置信度默认至少0.85、二级至少0.82，否则保持为空。成功弃权不会用本地低置信结果补齐；接口异常时才按 `BGM_CLOUD_FALLBACK_LOCAL` 决定是否回退本地。UCS与推荐标签请求共享 `BGM_CLOUD_MAX_CONCURRENCY` 并分别缓存。

推荐标签节点包含稳定 `code`、显示名称、说明、示例和子节点。以后可直接修改 `bgm_v2/resources/recommended_taxonomy.json`：新增或删除节点会在下次启动时同步到数据库；修改显示名称时保留原 `code`。标签体系发生变化后重新执行“一键建立检索库”，系统会清除旧的自动音效标签并按新候选重新分析，用户自定义标签不受影响。

网页服务启动时会先加载并预热 CLAP 检索模型，终端显示“模型加载完成”后才开始监听端口。因此启动时间会增加且服务运行期间会持续占用模型内存，但首次自然语言检索不再承担模型冷启动时间。“一键建立检索库”分析完成后也会重新预热检索模型。

UCS、推荐标签、乐器/材质的 CLAP 文本向量会持久化保存在本地数据库 `tag_embedding` 表中，服务重启后继续复用。缓存使用标签内容哈希校验：新增节点只生成新增项，修改名称、路径、描述或示例只重算受影响项，删除节点会通过外键级联同步删除缓存；更换 CLAP 模型时会为新模型建立独立缓存。

乐器/材质采用准确率优先的“分级优先、冲突否决”策略，而不是把所有证据简单加权：首先让 CLAP 沿现有标签树分析音频内容，得分和领先差距均足够时产生候选；音频模型不能确认时，才依次使用文件名/元数据中的明确标签名称，以及文件名与音频描述的一致结果。明确文本与较可靠的音频判断冲突时不写入标签。材质继续遵循“先动作、后材质”，但不依赖写死的动作或素材名称：除可靠的 AST 动作/事件外，CLAP 材质候选还必须得到明确材质名称，或文件名/音频描述语义的独立一致确认。只有动作名称而没有材质证据时保持为空。系统只保留到证据可靠的最深层，任何层级证据不足都会放弃该分支。动作分析结果和标签向量均持久化到本地，素材与标签未修改时不会重复计算。

标签向量在服务启动、网页开放前自动校验并按每 16 个一批持久化。首次启动或数据库被删除后会生成完整缓存；正常重启直接复用；新增或修改标签时仅更新受影响节点。建立素材检索库本身也支持断点继续，动作条件材质向量和后台任务阶段进度均持久化到数据库；程序异常退出后，重新启动并点击“继续建立检索库”即可跳过已完成内容。运行过程中可点击“安全停止”，系统会在当前素材或当前小批次落盘后退出。

每条素材、每套自动标签体系另有独立的“已计算”完成状态，空结果也会记录。本地或云端一旦完成 UCS、推荐标签、乐器/材质或音乐标签分析，后续扫描、重启、切换本地/云端提供方以及重复点击建库都不会重新计算，也不会因模型或标签树版本变化自动覆盖。历史自动标签和历史云端缓存会自动迁移为已完成。只有用户删除素材记录（单条或批量删除）时，对应完成状态、标签、向量和缓存才随记录级联删除；之后重新扫描该文件会作为新记录重新计算。

NVIDIA 显卡可用时，CLAP 与 AST 会按阶段串行使用 CUDA，BGE 固定使用 CPU。AST 在 4GB 显存设备上默认批次为 2；显存不足时先自动降为 1，仍不足再回退 CPU。CLAP 在加载或推理阶段显存不足时也会自动回退 CPU。可通过 `BGM_AST_BATCH_SIZE` 覆盖 AST 批次大小。运行状态会显示 AST 实际使用的设备和批次。

建立检索库前会检测内容完全相同的音效：先按文件大小筛选候选，再计算 SHA-256，只有字节完全一致才视为重复。确认框会显示音效总数、重复数量和实际索引数量。每组保留最早入库的一条用于检索，重复项不生成向量也不出现在结果中，但源音频文件不会被删除。文件未修改时会复用哈希结果。

输入框采用三路混合检索：精确匹配文件名、标签和元数据；使用 `BAAI/bge-small-zh-v1.5` 对文件名、完整标签路径和元数据进行中文文本语义匹配；使用 CLAP 匹配查询描述与真实音频内容。默认融合权重为文本语义 45%、音频语义 40%、精确关键词 15%，明确的关键词命中在最终排序中优先。BGE 模型固定在 CPU 运行以节省显存，并在服务启动时加载、补齐缺失文本向量；建立检索库或人工修改标签后自动同步受影响向量。启动过程仅使用本地模型缓存，请先运行 `下载本地模型.ps1`。

推荐标签采用以约 80% 准确率为目标的逐层分类，标签树本身不变。本地 AST 会从多个代表性片段生成由声音事件及概率支撑的结构化音频描述，并持久化到 `effect_caption_analysis`；每一层动态融合该描述的 BGE 语义、文件名/元数据语义、CLAP 原始音频语义和 AST 动作证据。父节点的内部语义说明会自动汇总现有直属子类，一级判断也会参考二级候选的最佳分数；描述性文件名与标签树后代名称的自然重合可作为证据，但不存在固定的文件名关键词映射。不能可靠进入子级时保留已确认的父级，强信号冲突时仍然弃权。素材没有修改时不会重复生成描述，详情区可查看实际参与判断的音频描述。

推荐标签保留内置 JSON 的原始树结构，内部采用联合判断：主类别按父子层级逐级缩小候选；速度、频段、音色、方向等属性容器分别独立判断。详情中的“确认推荐标签”允许用户人工确认多个节点，确认结果不会被自动建库覆盖，并会作为该节点及其父级的本地参考音频原型参与后续分类。

切换到音效搜索后，可以选择任意树节点筛选；选择父节点会同时匹配其所有后代标签。在音效结果卡片中点击“管理音效标签”，可以逐层进入并给素材标记。每个节点右侧显示的是它的直接子标签数量，不是整棵后代总数。

默认模型为 `MIT/ast-finetuned-audioset-10-10-0.4593`。首次使用需联网下载约 346 MB 的 `safetensors` 权重，之后从本机缓存读取；分析过程不会上传音频。CPU 可以运行，但建议先将“数量上限”设为 10 验证效果。可通过 `BGM_ANALYSIS_MODEL` 指向已经下载好的本地模型目录。
